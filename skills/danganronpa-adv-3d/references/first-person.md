# 第一人称、碰撞与交互

本文件描述可复用的第一人称运行时。实现时优先使用 `templates/runtime/first-person.js` 与 `templates/runtime/collision.js`，只替换配置与场景碰撞体。

## 1. 相机与坐标

- 相机使用 `YXZ` 欧拉顺序。
- `yaw` 绕 Y 轴；`pitch` 绕 X 轴。
- 初始朝向由场景配置；不要依赖默认相机方向。
- 眼高固定 1.80 m（基准值）；视点起伏只改变相机 Y，不改变碰撞体/玩家位置的高度。
- 俯仰限制约 `±83°`（`π/2 - 0.12`）。
- yaw 不做范围限制，允许 360°。

## 2. 参数

| 参数 | 默认 |
|---|---|
| 眼高 | 1.80 m |
| 玩家半径 | 0.30 m |
| 步行速度 | 2.6 m/s |
| 跑步速度 | 6.2 m/s |
| 加速度 | 14.0 |
| 鼠标灵敏度（窗口） | 0.0028 |
| 鼠标灵敏度（指针锁定） | 0.00215 |
| 俯仰限制 | ±83° |
| 中键回正 | 0.6 s，ease-in-out |
| 碰撞子步进 | ≤ 0.075 m |
| 碰撞迭代 | 3 pass |
| 步行起伏 | ±1.4 cm |
| 跑步起伏 | ±2.8 cm |
| 起伏频率 | 6.4 + speed × 1.15 |
| 侧倾 | 约 ±0.005 rad（跑步） |
| 停止归位 | 0.25 s 内 |

## 3. 移动

```text
forward = (-sin(yaw), -cos(yaw))
right   = ( cos(yaw), -sin(yaw))
desired = normalize(forward * f + right * r) * maxSpeed
velocity += (desired - velocity) * (1 - exp(-acceleration * dt))
```

- `W/S` 控制 f，`D/A` 控制 r。
- `Shift` 切换到跑步速度。
- 斜向输入归一化，不能比直线更快。
- 速度低于 0.001 时归零，避免漂移。
- 移动后按子步进拆分位移，每一步都调用碰撞 resolve。

## 4. 视点起伏

- 用速度比例增强，不要只在走路时固定幅度。
- `speedNorm = min(2.0, speed / walkSpeed)`。
- `bobAmount → bobHeight * speedNorm`。
- `bobPhase += dt * (bobFrequency + speed * 1.15)`。
- 垂直：`sin(bobPhase * 2) * bobAmount`。
- 横向：`cos(bobPhase) * bobAmount * 0.5`，沿相机 right 方向偏移。
- 侧倾：`sin(bobPhase) * bobRoll * speedNorm`。
- 用 `damp` 平滑振幅与侧倾；停止后自然归位。
- 跑步起伏必须明显强于步行；但横向偏移应小于 2 cm，避免穿墙。

## 5. 碰撞模型

### 5.1 玩家

- 水平圆，半径 0.30 m。
- 只处理 X/Z；Y 由眼高决定，不参与碰撞。
- 相机位置 = 玩家位置 + 横向 bob；碰撞仍以玩家中心为准。

### 5.2 碰撞体

- 墙体：AABB/OBB。
- 桌面、柜体、门扇、抽屉：OBB（`x, z, hx, hz, rot, active`）。
- 椅子：独立小 OBB，不要并入桌子。
- 圆形柱/花盆：可选 circle。
- 动态碰撞：门/抽屉每帧更新 `x/z/rot/active`。

### 5.3 Resolve

对每个碰撞体：

1. 将玩家中心变换到碰撞体局部坐标。
2. 找到局部矩形上最近点。
3. 若距离 < 半径，沿最近点方向推出。
4. 若中心在矩形内部，沿最小穿透轴推出。
5. 将修正量变换回世界坐标。
6. 最多 3 pass；没有移动时提前结束。

要求：

- 滑动而不是硬停。
- 角落不能抖动/卡死。
- 高速移动不能穿透（子步进）。
- 玩家不能从桌子下方穿过。

| 输入 | 行为 |
|---|---|
| `W A S D` | 平移 |
| `Shift` | 加速 |
| 左键拖动（非全屏） | 环顾 |
| 鼠标移动（全屏指针锁定） | 环顾 |

## 7. 全屏与指针锁定

- 页面按钮调用 `document.documentElement.requestFullscreen()`。
- 进入全屏后请求 `canvas.requestPointerLock()`。
- `pointerlockchange` 同步状态；失败时保留拖动 fallback。
- 退出全屏时退出指针锁定，恢复 HUD/FPS。
- 全屏时隐藏装饰性 HUD 与 FPS，保留准星、交互提示、必要 Toast。
- `F11` 若被浏览器原生接管，页面仍要保证退出后状态一致；不要因为 F11 让 HUD 永久隐藏或指针永久锁定。
- 切换场景时，先退出旧场景的拖动/锁定状态，再应用新相机。

## 8. 交互

- 每帧从相机中心（全屏）或鼠标位置（窗口）发射射线。
- 只对当前场景的可交互 mesh 做 raycast；不要把隐藏场景也算进去。
- 命中后从 `userData.interactiveId` 取对象。
- 提示：
  - 可开：`打开 + 名称`
  - 可关：`关闭 + 名称`
  - 锁定：`名称 + 暂未开放`
- `E` 或单击触发；拖动超过阈值不触发。
- 交互距离：餐厅约 3.9 m；宿舍按场景需要。
- 门/抽屉动画必须更新碰撞体。
- 锁定门不改变几何，只给提示并保留 `sceneId`。

## 9. 场景切换

- 每个场景保存自己的相机状态：
  - 行走场景：`{x, z, yaw, pitch}`；
  - 固定视点场景：`{yaw, pitch}`。
- 切换时：
  1. 保存当前视角；
  2. 禁用旧控制器，清空按键；
  3. 切换 active scene；
  4. 恢复目标视角/相机；
  5. 重置 frozen；
  6. 标记 hover 需要刷新；
  7. 触发阴影重烘焙。
- 不刷新页面。

## 10. 常见错误

- `Vector2` 当 `Vector3` 用，`position.z` 为 `undefined`，导致相机 NaN、黑屏。
- 只在初始化时设置一次相机，之后切换场景不恢复。
- 鼠标 Y 反转。
- 俯仰超过 ±90°，画面倒置。
- 只用一个大 box 包住桌椅，四角走不进去。
- 开门后不更新碰撞，玩家穿门。
- 窗口模式拖动时把单击也当互动，导致误开。
- 全屏请求失败后没有拖动 fallback。
- 切换场景后旧按键仍生效，玩家自己往前走。

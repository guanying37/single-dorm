# 弹丸论破风格 ADV 3D 场景

## 这个 skill 解决什么

把「学生餐厅 / 单人宿舍」做成可离线运行、可第一人称行走、可交互、可验收的 Three.js 场景。交付物不是效果图，而是一个能打开、能走、能开关家具、能通过性能与视觉验收的静态页面。

默认以当前项目的餐厅与宿舍为 reference case，但规则要能复用到同类 ADV 室内场景。当前项目定案与通用规则的边界见 `references/requirements.md`。

## 硬约束

以下规则不能被“性能优化”“视觉更好看”或“实现方便”绕开：

1. **完全离线**：无 CDN、无外部字体、无网络请求；Three.js 与全部素材本地化。
2. **场景内无人物、无文字/字体贴图、无音频**。UI 文字不属于场景贴图。
3. **不自行绘制新的画作**：画像必须是食物主题，使用用户提供的参考图；没有参考图时，用程序化 3D 浅浮雕，不要生成二维画。
4. **多场景必须在同一页面切换**：不能出现“另一个场景打不开”“两个页面互相找不到入口”。默认 `/` 显示宿舍，`/#dining` 显示餐厅，`/dining/` 跳转到 `/#dining`。
5. **所有投影主光的方向必须是世界坐标 `(0, -1, 0)`**，也就是垂直向下；不允许侧向 key/fill 投出方向矛盾的影子。
6. **宿舍只能有吊灯主光**：删除 windowSpill、侧向 fill 等第二主光；垂直向下的定向光作为吊灯的“投影代理”，不新增可见灯具。
7. **第一人称必须有碰撞**：不能穿墙、穿桌、穿椅、穿门；开门/拉抽屉时碰撞同步；不能卡死。
8. **本地必须通过 HTTP 打开**：`file://` 下 ES Modules 会被 CORS 拦截；页面要显示明确提示，不能白屏。
9. **性能底线 30 FPS，目标 60 FPS**；1920×1080 稳定接近 60 FPS。
10. **禁止不合理结构**：门后套门、漂浮叶片、整块桌位大碰撞盒、明显穿模、黑洞、接缝。

## 工作流

### 0. 先看现状，不要直接重建

- 启动本地服务器，打开现有页面，记录 console、404、首屏时间。
- 截图当前状态；测量 FPS、draw calls、三角面、贴图数。
- 找到已有的 `scene`、`player`、`collision`、`server` 文件；优先修复，不重复造。

### 1. 写验收矩阵

在动手前把需求翻译成可测试项：

- 数量：桌、椅、餐具、花、画、钟、灯、空调、监控、门、植物、扬声器。
- 空间：尺寸、桌距、门洞、走廊、净高。
- 行为：WASD、Shift、右键、中键、E、单击、F11。
- 物理：墙/桌/椅/门/抽屉碰撞。
- 视觉：影子方向、无穿模/接缝/漂浮、无门后套门。
- 性能：30 FPS 底线、60 FPS 目标、draw calls、三角面、贴图。
- 集成：同页切换、路由、`file://` 提示。

### 2. 锁空间骨架

- 先做地面、墙体、天花、门洞、走廊，不做家具。
- 墙厚、门洞、门套、踢脚线、椅线一次定好，避免后期家具穿墙。
- 用玩家半径 0.30 m 检查所有门洞与桌间通道。

### 3. 静态几何与材质

- 按材质合并静态几何；场景稳定后不再新增 geometry。
- 所有纹理程序化生成本地化，单张 ≤ 1024²。
- 先生成材质与 UV，再批量建家具；不要每把椅子一个 draw call。

### 4. 家具与陈设

- 先桌/椅/桌布/餐具，再花瓶/花，再画像/挂钟/绿植/扬声器。
- 植物必须按「主干 → 主枝 → 次枝 → 叶柄 → 叶片」建层级，每片叶有可见连接。
- 画像没有参考图时用 3D 浅浮雕；不要自己画二维图。
- 走廊端墙用边柜 + 壁灯收口，不要放第二道门。

### 5. 灯光与阴影

- 只指定一个投影主光，方向垂直向下。
- 餐厅：一盏垂直向下的定向光承载阴影；3 盏聚光灯只做光池，`castShadow = false`；洗墙灯不投影。
- 宿舍：吊灯作为唯一主光；删除侧向 fill 与 windowSpill；垂直定向光作为吊灯投影代理。
- 阴影静态烘焙一次；动态门/抽屉 `castShadow = false`。
- 定向光垂直向下时设置 `shadow.camera.up`，避免 lookAt 退化。

### 6. 第一人称与碰撞

- 眼高固定 1.80 m；步行 2.6、跑步 6.2；加速度与阻尼。
- 俯仰限制 ±83°；yaw 无上限；无侧翻/倒置。
- 视点起伏：步行约 ±1.4 cm，跑步约 ±2.8 cm；横向摆动与侧倾；停止 0.25 s 内归位。
- 碰撞用圆形玩家 vs AABB/OBB；子步进 ≤ 0.075 m；多次 resolve 防卡角。
- 餐桌不要整块大盒子：桌面 + 每把椅子独立碰撞；四个无椅角可走近。

### 7. 交互

- 准星/鼠标命中显示「打开/关闭 + 名称」。
- E 或单击触发；锁定门给明确提示。
- 正门双开/双关、餐具柜门、抽屉；动态碰撞随动画更新。
- 服务门保留 `sceneId`，以后接场景切换。
- 时钟通过 API 设置。

### 8. 同页集成

- 一个 renderer、两个 scene 实例；只渲染当前场景。
- 顶部固定「单人宿舍 / 学生餐厅」切换；不刷新页面。
- 切换时保存当前视角、恢复另一场景视角；清空按键，避免切场景后自己走动。
- `/` 默认宿舍；`/#dining` 餐厅；`/dining/` 重定向。
- 独立页可作为 fallback，但不能作为唯一入口。

### 9. 本地预览

- 提供 `start-preview.cmd` 与 `serve.py`。
- 启动后打开 `http://127.0.0.1:8123/#dining`。
- 端口被占用时直接打开已有预览，不要报错退出。
- `file://` 打开时显示明确提示，不能白屏。

### 10. 验收

- 先跑功能与碰撞，再跑视觉，最后跑性能。
- 1920×1080 实测 FPS；记录 draw calls、三角面、贴图数。
- 截图至少覆盖：总览、餐桌、餐具柜、门/走廊、时钟、植物、扬声器、两个场景。
- 检查 console 无报错、无 404、无外部请求。
- 没有实测数据，不允许写“已通过”。

## 代码模板

`templates/` 提供可复制骨架，不直接等于当前项目：

| 模板 | 用途 |
|---|---|
| `templates/scaffold/index.html` | 画布、HUD、import map、双场景挂载点 |
| `templates/scaffold/styles.css` | 共享预览 UI、全屏/准星/Toast |
| `templates/scaffold/src/hub.js` | 双场景切换、路由、输入分发、FPS |
| `templates/runtime/first-person.js` | 第一人称移动、跑步晃动、回正 |
| `templates/runtime/collision.js` | 圆 vs AABB/OBB、滑动、防卡角 |
| `templates/runtime/static-builder.js` | 按材质合并、静态批处理 |
| `templates/preview/serve.py` | 本地服务器、自动开浏览器、端口占用处理 |
| `templates/preview/start-preview.cmd` | Windows 一键启动 |
| `templates/validation/capture.mjs` | 截图与 console 检查 |
| `templates/validation/checklist.md` | 验收清单 |

使用模板时：

1. 先复制到目标项目，不要从模板目录直接运行。
2. 保留接口与碰撞/输入契约，只替换场景内容。
3. 改完必须重新测 FPS、碰撞、同页切换和 `file://` 提示。

## 禁止的偷懒

- 用一盏侧向定向光“让画面更有立体感”，导致影子方向与灯不一致。
- 用一整块桌位碰撞盒包住桌子和椅子，导致四个空角走不进去。
- 把两个场景做成两个互不链接的页面，或只给一个入口。
- 直接双击 `index.html` 交付，不提供本地服务器。
- 用漂浮面片当树叶，不建枝干/叶柄层级。
- 用自绘位图当食物画。
- 只改代码不跑页面，凭代码判断“应该没问题”。

## 完成定义

只有同时满足以下条件才算完成：

- [ ] 页面可通过本地 HTTP 打开，`file://` 有明确提示。
- [ ] 餐厅/宿舍同页顶部切换，三个路由都正确。
- [ ] 数量、空间、门、家具、陈设符合验收矩阵。
- [ ] 第一人称、跑步晃动、碰撞、交互全部实测。
- [ ] 所有投影方向垂直向下；宿舍只有吊灯主光。
- [ ] 无人物/文字贴图/音频/外部请求/自绘画作。
- [ ] 无门后套门、漂浮叶片、整块桌碰撞、明显穿模。
- [ ] 1920×1080 下 ≥30 FPS，目标接近 60 FPS；无 console 报错。
- [ ] 预览截图与验收记录已更新。
